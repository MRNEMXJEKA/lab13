# Практична робота №13

## Односторінкові застосунки (SPA) та клієнтська маршрутизація

### Формат

Комп'ютерний практикум

### Мета роботи

Перетворити застосунок на просту SPA (Single Page Application): реалізувати клієнтську маршрутизацію без фреймворку - hash-based роутинг (`location.hash`) чи History API (`pushState`/`popstate`) - і рендерити різні «сторінки» застосунку в один контейнер без перезавантаження браузера. Щонайменше 3 маршрути (у тому числі один із параметром на кшталт `/items/:id`) повторно використовують уже написані функції рендеру й дані з localStorage/IndexedDB.

### Варіант завдання

**Варіант 7 — Список бажань (Wishlist)**

| Маршрут | Сторінка |
|---|---|
| `/` | список бажаних товарів |
| `/wishes/:id` | деталі товару (`price`, `url`) |
| `/purchased` | фільтр уже куплених (`purchased: true`) |

### Хід роботи

**Крок 1. Вибір підходу**
Обрано **hash-based роутинг**: адреса маршруту зберігається після `#` (наприклад, `index.html#/wishes/21`). Браузер не надсилає цю частину URL на сервер, тому перехід між «сторінками» не породжує нового запиту документа, а F5 на будь-якому маршруті працює без налаштування сервера.

**Крок 2. Контейнер сторінки**
У розмітці виділено один контейнер `<main id="page-view">`, у який рендеряться всі «сторінки»: список, деталі товару та «Не знайдено». Блок «Сума» та шапка з меню лишаються спільними для всіх маршрутів.

**Крок 3. Таблиця маршрутів**
У `script.js` описано масив `routes` - патерн шляху → view-функція:

```js
const routes = [
  { path: "/", view: viewHome },
  { path: "/wishes/:id", view: viewWishDetail },
  { path: "/purchased", view: viewPurchased },
];
```

**Крок 4. Функція matchRoute(path)**
`matchRoute` розбиває поточний шлях і кожен патерн на сегменти по `/`, порівнює їх і для сегментів із `:` записує значення в об'єкт `params` (наприклад, `{ id: "21" }`). Якщо жоден патерн не підійшов - повертає `null`.

**Крок 5. View-функції**
- `viewHome()` - усі бажання й форма додавання;
- `viewPurchased()` - лише куплені бажання;
- `viewWishDetail(params)` - деталі товару за `params.id`;
- `viewNotFound(path)` - сторінка «Не знайдено».

Кожна view-функція описує вміст контейнера `#page-view`, а Vue перемальовує його. Картки рендерить той самий компонент `WishItem`, що замінив функцію рендеру з практикуму 7, а дані беруться з IndexedDB/localStorage (практикум 11) - розмітка й логіка не дублюються.

**Крок 6. Клієнтська навігація**
Посилання меню, назви товарів у картках, «← До списку» і «На головну» позначено атрибутом `data-link`. Один обробник `click` на `document` перехоплює кліки по них, викликає `preventDefault()` і `navigate(path)`, яка змінює `location.hash` замість звичайного переходу.

**Крок 7. Обробка hashchange**
Функція `render()` підписана на подію `hashchange`, тож кнопки «назад»/«вперед» браузера й ручна зміна адреси перемальовують вміст відповідно до нового шляху. Активний пункт меню підсвічується атрибутом `aria-current="page"`.

**Крок 8. Сторінка деталей**
Маршрут `/wishes/:id` знаходить запис за `id` серед бажань (обчислювана властивість `currentWish`) і показує лише його: ціну, посилання на товар, статус «куплено», пріоритет і саму картку з прогрес-баром. Видалення товару зі сторінки деталей повертає до списку.

**Крок 9. Неіснуючий маршрут**
Якщо `matchRoute()` повертає `null` або товару з таким `id` немає, показується сторінка «Сторінку не знайдено» з адресою, яку не вдалося відкрити, і посиланням «На головну».

**Крок 10. Перевірка навігації браузера**
Перехід `/` → `/wishes/2` → `/purchased`, потім «назад», «назад», «вперед», «вперед» - вміст на кожному кроці відповідає адресному рядку. F5 на будь-якому маршруті відкриває ту саму сторінку. На вкладці Network під час переходів немає нових запитів типу `document`.

**Крок 11. Коментарі та збереження**
Над таблицею маршрутів, `matchRoute`, view-функціями, `render` і обробником кліків додано коментарі, зміни зафіксовано в Git.

```
git add .
git commit -m "Практична робота №13: SPA з hash-роутингом — маршрути /, /wishes/:id, /purchased, сторінка «Не знайдено»"
git push
```

### Як працює роутер

```
клік по <a data-link>  →  navigate(path)  →  location.hash = path
                                                   ↓
                                         подія hashchange
                                                   ↓
render(): шлях з location.hash → matchRoute(path) → view-функція → vm.route
                                                   ↓
                         Vue перемальовує контейнер #page-view
```

### Маршрути й view-функції

| Маршрут | View-функція | Що показує |
|---|---|---|
| `#/` | `viewHome()` | форма додавання + усі бажання |
| `#/wishes/:id` | `viewWishDetail(params)` | ціна, посилання, статус, пріоритет і картка одного товару |
| `#/purchased` | `viewPurchased()` | лише куплені бажання |
| будь-який інший | `viewNotFound(path)` | «Сторінку не знайдено» + «На головну» |

### Висновок

У результаті виконання практичної роботи застосунок «Список бажань» перетворено на односторінковий (SPA) з клієнтською hash-маршрутизацією без бібліотеки-роутера. Маршрути описано таблицею `routes`, а функція `matchRoute` зіставляє шлях із патернами та витягує параметр `:id`. Три маршрути - список усіх бажань, деталі товару та фільтр куплених - рендеряться в один контейнер `#page-view` і повторно використовують компонент картки та дані з IndexedDB. Внутрішні посилання з атрибутом `data-link` перехоплюються й змінюють хеш, а подія `hashchange` синхронізує вміст з адресним рядком, зокрема для кнопок «назад» і «вперед». Для неіснуючих маршрутів і товарів показується сторінка «Не знайдено». Перехід між сторінками не перезавантажує документ, що перевірено на вкладці Network.
